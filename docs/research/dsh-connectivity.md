# DSH connectivity reuse evidence

Inspected upstream HEAD `c291e7961a515f6d7af9304e7fd1d257929aef26` on 2026-09-11. These are source observations, not packed-plugin, deployment or live-provider validation. Each facility is optional; Autopilot does not need to enable every transport. [Plugin design](../specs/plugin.md) and [providers](../specs/providers.md) own product choices.

## Host and Web API

| Need | Public DSH surface | Reuse and limits |
| --- | --- | --- |
| Same-process plugin calls | Injected Cordis services | Call the owning service directly; SDK, HTTP and MCP are not prerequisites for internal calls. |
| Typed Web commands/queries | `TypertRemoteService`, `bindTypertRemote`, `Remote`, `RemoteScope`, `RemoteError` from `@deepseek-ai/dsh-typert-protocol`; `ctx.typertGateway` and Client `ctx.remote` from `@deepseek-ai/dsh-api-gateway` / `./client` | Reuse generated argument/result validation, scoped resolution, cancellation and failure vocabulary. A decorator alone does not publish a callable Client method. | Live run updates | `@Remote({ mode: 'stream' })`; `RemoteStream`, `RemoteSnapshotStream`, `RemoteJournalStream` from `@deepseek-ai/dsh-api-gateway/client` | Supported generated streams share Gateway's mux/recovery. Autopilot still owns domain revisions, replay cursors, redaction and replacement snapshots; arbitrary unmarked iterables are insufficient. [Assembly](https://github.com/deepseek-ai/deepseek-harness/blob/c291e7961a515f6d7af9304e7fd1d257929aef26/packages/api/remotes/README.md#use-this-package). |

External Remote composition has existing building blocks: generate Host `./typert` and Client-safe `./remote` artifacts using `typertPlugin()` from `@deepseek-ai/dsh-typert-generator/tsdown`; publish generated files; let `@deepseek-ai/dsh-typert-loader` discover Loader entries, or explicitly register nested contributions; mount the external contribution with `ctx.remote.$mount()` in its own Client assembly. Consumers inject `remote.<namespace>`. Do not edit upstream's central assembly. The external repository still needs an isolated build/install proof of this generation pipeline. [Generator](https://github.com/deepseek-ai/deepseek-harness/blob/c291e7961a515f6d7af9304e7fd1d257929aef26/packages/typert/generator/README.md#publishing-typert-artifacts-from-a-package), [loader](https://github.com/deepseek-ai/deepseek-harness/blob/c291e7961a515f6d7af9304e7fd1d257929aef26/packages/typert/loader/README.md#use-this-package), [effect-owned mount](https://github.com/deepseek-ai/deepseek-harness/blob/c291e7961a515f6d7af9304e7fd1d257929aef26/packages/api/gateway/src/client/index.ts#L201).

`ctx.remote.$on` only receives the application's selected events. Gateway permits one forwarded-event source; an external plugin cannot register a competing source beside API Remotes. Prefer its own declared stream when new domain events are needed. Ordinary forwarded notifications are not replayed. [Selection](https://github.com/deepseek-ai/deepseek-harness/blob/c291e7961a515f6d7af9304e7fd1d257929aef26/packages/api/remotes/README.md#forwarded-host-events), [single source](https://github.com/deepseek-ai/deepseek-harness/blob/c291e7961a515f6d7af9304e7fd1d257929aef26/packages/api/gateway/src/index.ts#L232).

Connection already owns `/api` Host/Origin checks and persistent browser authentication. Raw `ctx.webServer.register()` routes do not inherit that policy automatically. Tracker ingress needs provider authentication, not browser-cookie authentication. Reusing browser transport also does not remove the Settings access restriction documented in [Web research](dsh-web.md). [Connection](https://github.com/deepseek-ai/deepseek-harness/blob/c291e7961a515f6d7af9304e7fd1d257929aef26/packages/client/connection/src/index.ts#L97), [route registry](https://github.com/deepseek-ai/deepseek-harness/blob/c291e7961a515f6d7af9304e7fd1d257929aef26/packages/host/webserver/README.md#summary).

## SDK and ACP are process transports

`@deepseek-ai/dsh-sdk-client` exports `DeepSeekHarness`, `HarnessSession` and `HarnessClient`; it starts a separate `dsh --profile sdk` process, owns shutdown, and speaks `@deepseek-ai/dsh-sdk-protocol` to `@deepseek-ai/dsh-sdk-jsonrpc-server`. It registers no Cordis service. `run()` collects receipt-to-idle activity, not a causally isolated prompt result; the protocol has no mid-turn cancel. It is an optional process-isolation choice, not the implementation API for a plugin already inside DSH. [Public entry](https://github.com/deepseek-ai/deepseek-harness/blob/c291e7961a515f6d7af9304e7fd1d257929aef26/packages/sdk/client/src/index.ts#L1), [limitations](https://github.com/deepseek-ai/deepseek-harness/blob/c291e7961a515f6d7af9304e7fd1d257929aef26/packages/sdk/client/README.md#known-limitations-and-deferred-work).

`@deepseek-ai/dsh-acp` is the alternative trusted stdio automation server: independent persistent sessions, resume, cancel, quiescent close and MCP attachment. It omits transcript replay and DSH Web presentation. `authenticate` succeeds without authentication; do not expose this as a public VPS control endpoint. [Protocol and limits](https://github.com/deepseek-ai/deepseek-harness/blob/c291e7961a515f6d7af9304e7fd1d257929aef26/packages/acp/acp/README.md#protocol-contract).

## MCP integration

`@deepseek-ai/dsh-mcp-client` exports its plugin/config and `McpResult` type, not a general `ctx.mcp` client service. Each configured stdio or Streamable HTTP server contributes namespaced tools to `ctx.tools`; discovery, reconnect, timeouts, cancellation and disposal are already implemented. `ctx.tools.execute()` is the existing programmatic policy pipeline; callers must satisfy scope, visibility and presentation-mode rules, including PTC restrictions. No additional MCP transport implementation is needed merely to use those tools. [Entry](https://github.com/deepseek-ai/deepseek-harness/blob/c291e7961a515f6d7af9304e7fd1d257929aef26/packages/mcp/mcp-client/src/index.ts#L1), [execution](https://github.com/deepseek-ai/deepseek-harness/blob/c291e7961a515f6d7af9304e7fd1d257929aef26/packages/core/tools/src/index.ts#L1304).

The inspected MCP package provides tools only, not resources/prompts or a production MCP server. No Jira/Linear provider is supplied by that bridge. A third-party server still needs conformance evidence for stable identities, human authorization, complete pagination and ambiguous-write reconciliation. All discovered tools enter the selected scope; avoid exposing mutation tools that bypass Autopilot publication policy. Unsupported output-schema vocabulary falls back to JSON, so provider validation remains necessary. Configured env/headers are materialized transport inputs, not an automatic per-call credential-reference resolver. [Capabilities and limits](https://github.com/deepseek-ai/deepseek-harness/blob/c291e7961a515f6d7af9304e7fd1d257929aef26/packages/mcp/mcp-client/README.md#known-limitations-and-deferred-work), [transport](https://github.com/deepseek-ai/deepseek-harness/blob/c291e7961a515f6d7af9304e7fd1d257929aef26/packages/mcp/mcp-client/src/transport.ts#L20).

Webhook reuse and its admission/durability limits belong to [Host platform evidence](dsh-platform.md#timing-ingress-and-git).
