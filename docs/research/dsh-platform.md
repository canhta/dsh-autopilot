# DSH Host platform reuse

Inspected upstream `c291e7961a515f6d7af9304e7fd1d257929aef26` on 2026-09-11. These are source findings, not installed-plugin or crash-recovery results. [Operations](../specs/operations.md) owns Autopilot requirements; [reuse selection](../specs/plugin.md#reuse-before-implementation) owns implementation discipline.

## Configuration and credentials

`@deepseek-ai/dsh-settings` exposes `ctx.settings`: namespace registration, schema defaults → composition base → user-layer resolution, owner validation, serialized writes, `expectedRevision` conflicts and change observation. `dsh-settings-file` supplies YAML/JSON persistence. Compose these for Autopilot configuration; retain only run-specific snapshots in the run store. A Settings revision fences configuration edits, not a transaction across run/admission records. [Service](https://github.com/deepseek-ai/deepseek-harness/blob/c291e7961a515f6d7af9304e7fd1d257929aef26/packages/settings/settings/src/index.ts), [file provider](https://github.com/deepseek-ai/deepseek-harness/blob/c291e7961a515f6d7af9304e7fd1d257929aef26/packages/settings/settings-file/README.md).

`@deepseek-ai/dsh-credentials` exposes `credentialRef`, `ctx.credentials.resolve/describe/set/unset` and durable record operations for grants. `dsh-credentials-local` supplies the store; `dsh-authorization` is the separate authorization capability. Resolve secrets per operation; use existing reference/record metadata for UI status. These facilities do not supply Jira/Linear-specific grants or grant permission merely because a reference exists. [Credential service](https://github.com/deepseek-ai/deepseek-harness/blob/c291e7961a515f6d7af9304e7fd1d257929aef26/packages/credentials/credentials/src/index.ts), [authorization](https://github.com/deepseek-ai/deepseek-harness/blob/c291e7961a515f6d7af9304e7fd1d257929aef26/packages/credentials/authorization/README.md).

Settings redaction is not a general secret-safety guarantee: the inspected walker misses secret fields hidden behind some schema compositions and may expose schema defaults. Autopilot configuration therefore carries credential references, not secrets/default secret values. Browser access restrictions and public editors are recorded in [Web evidence](dsh-web.md). [Documented limitation](https://github.com/deepseek-ai/deepseek-harness/blob/c291e7961a515f6d7af9304e7fd1d257929aef26/packages/settings/settings/README.md#known-limitations-and-deferred-work).

## Durable storage fit

Candidate composition: `@deepseek-ai/dsh-storage`, `dsh-storage-domain` and an existing `dsh-storage-sqlite` or `dsh-storage-json` provider, subject to the atomicity proof required by [operations](../specs/operations.md#durable-state). Public domain exports include `defineDomain`, `domainTable` and `ctx.storageDomain.open`; handles expose tables, `update`, global values and `close`. The domain serializes writes and publishes memory/change events after persistence succeeds; opening validates stored records. This is directly relevant to non-Session Autopilot records, not a reason to write a new persistence framework. [Public entry](https://github.com/deepseek-ai/deepseek-harness/blob/c291e7961a515f6d7af9304e7fd1d257929aef26/packages/storage/storage-domain/src/index.ts), [domain operations](https://github.com/deepseek-ai/deepseek-harness/blob/c291e7961a515f6d7af9304e7fd1d257929aef26/packages/storage/storage-domain/src/domain.ts).

Atomicity is per record; there are no public cross-record/table transactions, secondary indexes or automatic migrations. A same-process single-open guard is not a cross-process dispatch lock. The SQLite provider's individual statements do not turn several domain writes into one transaction. An aggregate record may fit coupled state and intents, but its size, rewrite cost and global budget coordination require validation; this is an inference, not a selected implementation. [Domain limits](https://github.com/deepseek-ai/deepseek-harness/blob/c291e7961a515f6d7af9304e7fd1d257929aef26/packages/storage/storage-domain/README.md#known-limitations-and-deferred-work), [SQLite provider](https://github.com/deepseek-ai/deepseek-harness/blob/c291e7961a515f6d7af9304e7fd1d257929aef26/packages/storage/storage-sqlite/README.md).

## Timing, ingress and Git

| Need | Existing capability and reuse limit |
| --- | --- |
| Global admission timing | `@deepseek-ai/dsh-schedule` owns durable Session-local reminders delivered to live roots, not cold ticket discovery, calendar admission windows or external notifications. Autopilot still owns those policies. [Schedule](https://github.com/deepseek-ai/deepseek-harness/blob/c291e7961a515f6d7af9304e7fd1d257929aef26/packages/schedule/schedule/README.md). |
| Authenticated ingress | `dsh-webhook` exposes `ctx.webhookRuntime.register/dispatch`; `dsh-webhook-github` verifies GitHub signatures on an existing Host route. Rules may execute trusted code and return no Session request. The runtime is process-local, with no durable queue/deduplication; its default Session creation must not bypass admission. It is not an outbound webhook sender or a Jira/Linear adapter. [Runtime](https://github.com/deepseek-ai/deepseek-harness/blob/c291e7961a515f6d7af9304e7fd1d257929aef26/packages/webhook/webhook/README.md), [adapter](https://github.com/deepseek-ai/deepseek-harness/blob/c291e7961a515f6d7af9304e7fd1d257929aef26/packages/webhook/webhook-github/src/index.ts). |
| Managed Git commands | `dsh-subprocess` supplies explicit argv/cwd, cancellation and managed process-range termination through `ctx.subprocess`; reuse its selected provider. `done` is command exit, while `waitForExit` covers managed-range quiescence. Autopilot owns Git arguments, validated paths and cleanup eligibility. [Subprocess](https://github.com/deepseek-ai/deepseek-harness/blob/c291e7961a515f6d7af9304e7fd1d257929aef26/packages/subprocess/subprocess/README.md). |
| Workspace association | `dsh-workspace` exposes `ctx.workspaceRegistry` for canonical workspace records and Session membership. It is not a Git worktree allocator or PR-aware cleanup policy. [Registry](https://github.com/deepseek-ai/deepseek-harness/blob/c291e7961a515f6d7af9304e7fd1d257929aef26/packages/workspace/workspace/src/index.ts). |

Use existing Cordis lifecycle effects for acquired resources. Headless process supervision and authenticated VPS transport remain deployment composition, not new Autopilot account, server or secret-management products.
