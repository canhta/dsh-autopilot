## Import and composition limits

Feature-plugin components are internal even when their source files contain `export`. `ProviderEditor`, `PluginCard` and plugin `fields.tsx` are not value exports from their public client entries. Neither a generic `SchemaForm` nor a reusable credential editor is exported at this baseline. Public props/types do not imply an importable React component. The upstream [export policy](https://github.com/deepseek-ai/deepseek-harness/blob/c291e7961a515f6d7af9304e7fd1d257929aef26/packages/client/AGENTS.md#export-discipline-client-plugin-packages) requires injected services and slots for cross-feature behavior/UI; static primitives/store libraries permit value imports.

Existing `ui-settings-plugins` can host Autopilot configuration without importing private renderers: register an Autopilot-owned card in `settings.plugin.item`, keyed by its Host-served settings namespace. Types come from `@deepseek-ai/dsh-client-ui-settings-plugins/client`. The existing configurable tab pairs namespaces with registered cards; it does not generate forms from arbitrary schemas. Its shipped cards edit specific DSH namespaces, not Autopilot. Reuse that placement or the dedicated `settings.section` placement without duplicating the editor; neither requires rebuilding Settings navigation or inventing a general form framework. [Public slot contract](https://github.com/deepseek-ai/deepseek-harness/blob/c291e7961a515f6d7af9304e7fd1d257929aef26/packages/client/ui-settings-plugins/src/client/slot-contract.ts#L1), [dispatch and extension rules](https://github.com/deepseek-ai/deepseek-harness/blob/c291e7961a515f6d7af9304e7fd1d257929aef26/packages/client/ui-settings-plugins/README.md#L28).

The [Modal implementation](https://github.com/deepseek-ai/deepseek-harness/blob/c291e7961a515f6d7af9304e7fd1d257929aef26/packages/client/ui-primitives/src/Modal.tsx#L38) supplies portal, Escape/mask close and dialog attributes, but contains no focus trap or focus restoration. Reuse requires composing the missing behavior to satisfy Autopilot's existing accessibility requirement.

## Browser packaging and transport

A dynamic plugin declares `dsh.client.platform: "web"` and exports built `./client`. Service `inject` controls activation; `dsh.client.inject` package edges are informational. Register foreign slots through `ctx.slots.inject` so declaration removal/remount is handled. [Module contract](https://github.com/deepseek-ai/deepseek-harness/blob/c291e7961a515f6d7af9304e7fd1d257929aef26/packages/client/modules/README.md#declaring-a-client-plugin), [plugin checklist](https://github.com/deepseek-ai/deepseek-harness/blob/c291e7961a515f6d7af9304e7fd1d257929aef26/packages/client/AGENTS.md#new-plugin-package-checklist).

React, Cordis, primitives, slots, store and dockkit are [shell-seeded modules](https://github.com/deepseek-ai/deepseek-harness/blob/c291e7961a515f6d7af9304e7fd1d257929aef26/packages/client/web/src/platform.ts#L8); do not duplicate them in `dsh.client.external` or use that field to import feature components. Static-library exports differ from dynamically injected services.

Reusing Settings UI does not solve VPS access; the authoritative [remote-access observations](dsh.md#remote-access-observations) describe persistence restrictions and candidate transport composition. No alternate credential store or replacement Web shell is implied.
